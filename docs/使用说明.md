# DevZen 使用说明

> 「先看见，再行动。」DevZen 不只是清理工具，更是你本地项目的清单。
>
> 本文面向**普通用户**，告诉你每个界面、每个按钮在做什么，以及典型场景下应该怎么操作。开发者向的架构文档请看 [`.qoder/repowiki/zh/content/`](../.qoder/repowiki/zh/content)。

## 这是什么 · 适合谁

DevZen 帮你回答四个问题：

1. **本地一共有哪些项目？** 自动识别 Node / Rust / Go / Python / Java / Xcode / SwiftPM 等生态
2. **它们来自哪里？** GitHub clone / 远程仓库 / 仅本地（无远程备份）
3. **占了多少空间，哪些可以安全删？** `node_modules`、`target`、`build` 这类构建产物
4. **不再活跃的项目怎么处理？** 安全卸载本地（保留 .git）→ 压缩冷备 → 删除原目录

特别适合这几类人：

- 用 AI 编程工具（Qoder / Trae / Cursor 等）大量产生小项目，记不清自己 clone 过 / 生成过哪些项目的人
- 磁盘吃紧、想清掉 `node_modules` 又怕误删源码的人
- 多设备多项目、有「过期项目想冷藏，又怕将来要找回来」需求的人

## 一、安装与首次启动

### 1. 下载安装包

去 [GitHub Releases](https://github.com/szgenle/devzen/releases) 下载最新的 `.dmg`，双击拖入「应用程序」即可。

### 2. 处理首次打开提示（macOS）

当前版本采用 ad-hoc 签名（开源项目的常见做法），未走 Apple 公证，首次打开会被 Gatekeeper 拦截。任选一种方式：

- **方式 A**：在「应用程序」中找到 DevZen，**右键 → 打开 → 仍要打开**（仅首次需要）
- **方式 B**：终端执行一条命令清除隔离属性
  ```bash
  xattr -cr /Applications/DevZen.app
  ```

### 3. 首次进入 · 先去设置一下

点右上角 ⚙ 进入「首选项」，建议先做两件事：

- **语言**：默认跟随系统，可手动切到 中文 / English
- **冷备包备份目录**：这是「完全归档」功能的前置条件，没设置时该按钮会被禁用。建议放在外置硬盘或 NAS 挂载点，比如 `/Volumes/Backup/devzen-bundles/`

> ⚠ **冷备包不要放公共云盘**（iCloud Drive / Dropbox 同步目录）。冷备包包含 `.env` 等本地配置和完整源码，公网同步有泄露风险。设置页底部也有这条提醒。

## 二、扫描你的项目

### 首次扫描

首页「扫描目录」默认填的是你的家目录（`~`）。直接点「开始扫描」，DevZen 会从这里递归往下找，**自动跳过** `Library/`、`Applications/`、`Downloads/` 等系统目录，最大递归深度 5 层，避免无谓的 IO。

如果你的项目放在固定子目录（比如 `~/Dev/`），点「换个目录」选过去，下次扫描会更快。

![首页](./assets/screenshots/1-home-zh.png)

### 扫描中

页面会显示**已扫描目录数**和**已发现项目数**两个实时计数。一般家目录扫完在 10 秒内（取决于项目数量与磁盘速度）。

### 再次进入 · 历史列表

只要扫过一次，下次启动 DevZen 首页就变成「扫描历史」列表。点条目直接看上次结果，不用每次重扫——清理是低频操作，没必要每次都重新扫一遍。

需要刷新数据时点条目右侧「重新扫描」即可。

## 三、看清单

扫完进入结果页，左上有两个 Tab：**概览** 和 **清理**。

### 概览（默认）

按项目维度展示，每行一个项目，关键信息一目了然：

- **项目名 + 一句话描述**：从 `package.json description` 或 README 第一段提取
- **生态徽标**：Node / Rust / Go / Java …
- **来源徽标**：
  - 蓝色「来自 GitHub」/「来自 GitLab」等：可重新 clone 找回，删了不心疼
  - 灰色「有远程备份」：识别到 remote 但未匹配已知托管商
  - **红色「仅本地」**：⚠ 没有 remote，删了就找不回来
- **可清理大小**：构建产物占用，灰色，悬停看明细
- **最近修改时间**：基于生态 marker 文件 mtime
- **「有修改」红点**：表示 git 工作区脏（有未提交的改动）

![概览列表](./assets/screenshots/4-overview-zh.png)

视图右上角 `▦ / ▤` 可切换**列表 / 卡片**两种密度。多项目时列表更紧凑，少项目时卡片更直观。

### 顶部筛选栏

- **搜索框**：按项目名或描述模糊匹配
- **分类**：工作 / 个人 / 第三方 / 本地草稿 / 自定义
- **生态**：只看 Node / 只看 Rust 等
- **来源**：仅本地 / 远程 / GitHub
- **标签**：按打过的标签过滤
- **「有修改」开关**：只看脏工作区项目（用来提醒自己别忘了 commit）

筛选条件叠加生效；状态栏右侧实时显示「N 个项目匹配」。

### 点击单个项目 → 详情面板

侧滑面板，分几个区块：

- **基本信息**：路径、生态、来源、最近修改、git 状态（带刷新按钮，外部 commit 后回来同步）
- **分类**：可手动指定分类、清除回到自动推断、新建自定义分类
- **标签**：随心打标签
- **可清理目录**：列出该项目下所有可被清理的目录及大小
- **快速启动**：一键用编辑器/终端打开（详见[第五节](#五一键启动到编辑器--终端)）
- **归档项目**：触发 archive 流程（详见[第六节](#六归档与冷备包关键概念)）

## 四、清理构建产物

### 切到「清理」Tab

每个项目下展开列出可清理目录（`node_modules` / `target` / `build` / `.next` / `dist` / `out` ...），勾选要删的，底部「清理选中」会汇总数量与预计释放空间。

![清理列表](./assets/screenshots/3-cleanup-zh.png)

操作建议：

- **不知道选什么** → 直接点表头「全选」，再去掉你想保留的
- **只想清最大的** → 列表已按可清理大小降序，从上往下勾几个就行
- **粒度到项目** → 项目左侧勾选框是「全选该项目下的可清理目录」

### 二次确认弹窗

点「清理选中」后会弹窗，里面会汇总：

- 将删除多少个目录、预计释放多少空间
- **如果选中的项目里有「仅本地」的，会用红色加粗强提醒**，并解释「这次只删构建产物不删项目本身，但请确认你知道自己在做什么」
- 可点「查看列表」展开完整路径列表

确认后开始删除，进度弹窗实时显示每个目录的删除结果。

### 清理进度弹窗

弹窗里逐行列出每个目录的清理状态（进行中 / 成功 / 失败），底部汇总释放空间。

- **取消清理**：点「取消」立即中断后续目录的删除。当前正在删的目录会先完成（避免删一半），已删完的结果保留
- **权限失败引导**：如果某个目录因权限不足删除失败（macOS 上尤为常见），弹窗顶部会出现引导横幅：
  - **macOS**：点「去开启权限」直接跳转到系统设置 → 隐私与安全性 → 完全磁盘访问权限，找到 DevZen 并打开开关，然后回来重新清理
  - **Windows / Linux**：按提示检查目录权限或以管理员身份运行

> 💡 **提示**：未签名的开发版（`make dist` 直接打包）在 macOS 上不会自动弹出权限申请弹窗，需要首次运行时手动到系统设置中把 DevZen.app 加入「完全磁盘访问权限」列表并打开开关。签名发行版则会在首次访问时自动触发系统授权弹窗。

### 安全护栏（你看不见但生效的）

DevZen 不会删任何**它不认识的目录**。每次清理都会校验：

1. 路径必须是绝对路径
2. 路径必须在你家目录内
3. 目录名必须在白名单内（`node_modules` / `target` / `build` / `dist` / `.next` / `out` / `.gradle` / `.dart_tool` / `Pods` 等）
4. 目录必须真实存在且为目录类型
5. 不跟随符号链接（防止穿透到家目录之外）

任意一项不通过都会拒绝执行，不会动文件。

## 六、归档与冷备包：关键概念

> ⚠ **这是 DevZen 最容易混淆的地方，请认真读这一节。**

很多用户把「归档」直觉理解为「打个包扔到备份盘 + 删除原目录」三件事一起做。DevZen 把它**拆成了两层**，由你按需组合：

| 层级 | 操作 | 改了什么 | 入口 |
|---|---|---|---|
| **第 1 层：瘦身** | **归档项目**（archive） | 删除 git tracked 源码 + 白名单大目录（`node_modules` 等）；**保留 `.git`、未跟踪文件、`.env`** | 项目详情面板「归档项目」按钮 |
| **第 2 层：冷备 + 删原目录** | **打包并清空目录**（bundle & remove） | 把整个已归档项目压缩成一个 `.tar.gz` 冷备包存到备份目录 → sha256 二次校验 → 校验通过后**永久删除原目录** | 已归档项目卡片「打包并清空目录」按钮（红字） |

为什么这么拆？

- **第 1 层瘦身后**，`.git` 还在，离线就能 `git restore .` 找回所有源码（DevZen 的「恢复」按钮就是这个）。所以「瘦身」是**可逆**的，无需确认成本太高
- **第 2 层删原目录**才是**真正不可逆**的操作。所以 DevZen 强制要求：**先有 bundle，再 sha256 校验通过，最后才动原目录**。任一步失败，原目录纹丝不动

### 6.1 第 1 层：归档（瘦身）

入口：项目详情面板 → 红色「归档项目」按钮。

**前置条件**：项目必须有远程仓库（remote URL）。「仅本地」项目这个按钮会被禁用——因为没远程就没退路。

弹窗里会做几件事：

1. **检测脏状态**：有未提交修改 / 未跟踪文件 / 未推送 commit 时会**强烈提醒**先 push
2. **展示要删什么**：tracked 源代码 + node_modules / build 等大目录
3. **展示要保留什么**：`.git`、未跟踪文件（如 `.env`、`local/`、本地脚本）、IDE 配置
4. 点「确认归档」执行；如果脏可以点「强制归档」（tracked 修改会丢，未跟踪保留）

执行后：

- 项目目录大幅瘦身，但你打开它仍然是个完整的 git 仓库
- 出现在首页「已归档项目」入口和「归档管理」页

### 6.2 已归档项目页

首页有了归档记录后，会出现一个 📦「已归档项目 · N」入口；点进去就是归档管理页。

![归档列表](./assets/screenshots/2-archives-zh.png)

每张卡片底部有两行按钮：

```
─────────────────────────────────────
[定位]                          [忘记]   ← 辅助操作
              [打包并清空目录] [恢复]    ← 核心操作
─────────────────────────────────────
```

- **定位**：在 Finder 中打开这个项目目录
- **忘记**：仅从 DevZen 列表中移除该记录，**不动任何本地文件**。适合「我不再用 DevZen 管理它了」的场景
- **打包并清空目录**：见下一节，红字危险操作
- **恢复**：从当前项目目录就地 `git restore .` 把 tracked 文件还原（前提是 `.git` 还在）

顶部还有搜索框、按归档时间/释放空间/项目名排序的工具栏。

### 6.3 第 2 层：打包并清空目录（完全归档）

入口：已归档项目卡片右下角红字「打包并清空目录」。

**前置条件**：

- 该项目已经走过第 1 层归档（卡片上能看见它）
- 已在「首选项」里配置了**冷备包备份目录**（否则按钮 disabled）

点击会弹二次确认，文案明确告诉你三件事：

> 确定打包并清空原目录？
>
> · 先生成冷备包并二次校验 sha256
>
> · 校验通过后**永久删除**原项目目录
>
> 该操作不可撤销。以后可从冷备包恢复回原路径或新位置。

确认后，DevZen 走的是这个事务化流程：

```
1. 在备份目录写一个 .tar.gz.tmp 临时包
2. rename 成最终 .tar.gz 文件 + 写索引
3. 重新读盘流式计算 sha256，对比索引中的值
4. 校验通过，再调用 fs.rm 递归删除原项目目录
```

任何一步失败，**原目录都还在**。删除前还会再做一次「路径必须在家目录内」校验。

执行成功后：

- 备份目录里多了一个 `.tar.gz`（项目元数据嵌在文件名 + 索引里）
- 该归档记录的「路径已不存在」标记变成生效（卡片上灰显）
- 但卡片本身还在（保留的是「这个项目曾经存在，且有 N 个冷备包」的记忆）

### 6.4 查看冷备包 / 校验 / 恢复

每个归档卡片顶部有「查看冷备包 · N」按钮，点开是一个**二级弹窗**（不是在卡片里展开），里面列出该项目所有冷备包：

| 字段 | 说明 |
|---|---|
| **包大小** | .tar.gz 占用 |
| **打包于** | 时间戳 |
| **sha256** | 哈希前 8 位（点「校验完整性」按钮可重算并对比） |
| **定位冷备包** | 在 Finder 中打开备份文件 |
| **校验完整性** | 重算 sha256，包损坏 / 被改过会立即发现 |
| **恢复…** | 弹「从冷备包恢复」对话框 |
| **删除冷备包** | 永久删除该 `.tar.gz` 文件 |

### 6.5 从冷备包恢复

点「恢复…」打开对话框：

- **冷备包**：来源文件路径
- **原始路径**：当初打包时这个项目所在的路径
- **恢复到**：默认勾选「使用原始路径」；可改成「选其他位置…」

点「开始恢复」后：

1. 先 sha256 校验冷备包是否完好
2. 解压到目标路径（要求**目标必须为空目录或不存在**，避免覆盖）
3. 完成后弹结果，可定位到 Finder

恢复后这个目录就是个完整的项目（含 `.git`、`.env`、源码、本地配置），你可以正常 `git pull`、`npm install`、继续干活。

### 6.6 三种状态对比表

| 项目状态 | 占用 | 源码可见 | `.git` | 远程 | 找回方式 |
|---|---|---|---|---|---|
| 正常 | 大 | ✅ | ✅ | 看仓库 | — |
| 瘦身后（archive） | 小 | ❌ | ✅ | 看仓库 | DevZen「恢复」一键 `git restore`（离线） |
| 完全归档后（bundle & remove） | 几乎 0 | ❌ | ❌（已删） | 看仓库 | DevZen「从冷备包恢复」（离线 / 全靠备份） |

## 七、重复项目检测

DevZen 会自动识别**同一仓库 clone 了多份**的情况（基于 remote URL + 目录名相似度）。这种项目在概览列表上会带一个橙色「重复 ×N」徽标，点徽标弹出对比弹窗：

弹窗里把每份副本逐行列出：路径、最后 commit、最后文件修改、未推送 commit、未提交修改、当前分支、项目大小、可清理大小。

DevZen 还会给出**自然语言建议**，例如：

- 「`A` 是最新副本（最后 commit 2 天前），建议保留」
- 「`B` 较新且已同步远程，`A` 可安全归档」
- 「`A` 有 3 个未推送的 commit，建议先推送再决定」
- 「所有副本均已同步远程，可放心归档任意旧副本」

弹窗里每行都有「归档此副本」「在 Finder 中定位」「清理构建产物」三个直达按钮。

## 九、安全策略（用户视角）

DevZen 在每一个删除路径上都设了护栏，对你而言这是**默认开启**的：

| 操作 | 护栏 |
|---|---|
| **清理构建产物** | 仅家目录内 / 仅白名单目录名 / 仅真实目录 / 不跟随 symlink / 二次确认弹窗 |
| **「仅本地」项目** | 清理弹窗里**红色加粗强提醒**「这些项目没有远程备份」 |
| **归档（瘦身）** | 必须有 remote / 脏状态强提醒 / `.git` 与未跟踪文件保留 / `.env` 等本地配置不删 |
| **打包并清空目录** | bundle 写盘成功 + sha256 二次校验通过后**才**删原目录 / 删前再次家目录边界校验 / 二次确认弹窗 |
| **删除冷备包** | 二次确认弹窗 |

特别说一下两条不会变的硬规则：

1. **任何写操作只发生在用户家目录内**。哪怕你手动选了 `/etc/`，DevZen 也会拒绝。
2. **任何删除操作前都会重新校验路径**。即使别人篡改了索引文件，路径越界也会拒绝执行。

## 十、常见问题 FAQ

**Q1：扫描出来的项目数为零？**

可能原因：
- 选错根目录了，回首页「换个目录」
- 该目录没有 marker 文件（`package.json` / `Cargo.toml` / `go.mod` / `pom.xml` / `*.xcodeproj` 等）
- 项目嵌套层级超过 5 层。可以选更深一级的目录作为根目录重新扫

**Q2：清理失败 / 部分目录没删掉？**

清理结果会给每个失败目录的具体错误。常见情况：
- 目录被某个进程占用（`vscode-server` / 编辑器索引服务）→ 关闭相关进程重试
- 权限不足（很罕见，家目录内不应该出现）→ 用 Finder 手动删

**Q3：归档失败，提示「检测到未保存到远程的内容」？**

说明项目有未推送的 commit / 未提交修改 / 未跟踪文件。建议先 commit + push；如果你确认这些可以丢，可以点「我已知风险，强制归档」。**未跟踪文件不会被强制归档删除**，只有 tracked 修改会丢。

**Q4：归档失败，提示「该项目没有远程备份」？**

「仅本地」项目无法用 archive 流程（删了就找不回）。如果你想长期冷藏一个仅本地项目，建议：
1. 先把它推到一个私有仓库（`git remote add origin ... && git push -u`）
2. 然后再走归档

或者直接走「打包并清空目录」？**目前不允许**，因为这条路径要求项目处于「已归档」状态。如有强需求可去 GitHub 提 Issue。

**Q5：「打包并清空目录」按钮是灰的？**

两种可能：
- 没设置冷备包备份目录 → 去首选项设置
- 原项目路径已不存在（之前已经删过）→ 这个按钮就没意义了

**Q6：恢复时报「目标路径已存在且非空」？**

「从冷备包恢复」要求目标必须为空目录或不存在，防止覆盖。把目标目录手动清空 / 改个新路径再试。

**Q7：sha256 校验失败 / 包文件丢失？**

冷备包文件被外部修改、磁盘损坏、文件被移走都会导致这个错误。可以点「定位冷备包」去文件管理器看一眼具体情况。**校验失败时不会去删原目录**——这是事务化设计的一部分。

**Q8：删了 DevZen 的归档记录（点了「忘记」），冷备包还在吗？**

在。「忘记」只移除 DevZen 自己的索引，不动 `.tar.gz` 文件。索引重建后这些 bundle 会以「孤立冷备包」分组单独显示。

**Q9：DevZen 数据存在哪里？**

- 扫描历史 / 视图模式 / 语言主题：`localStorage`（渲染层浏览器存储）
- 备份目录、归档索引、冷备包索引：`~/Library/Application Support/DevZen/`（macOS userData 目录）
- 卸载 DevZen 不会删上面这些数据；如需彻底清除，手动删 `~/Library/Application Support/DevZen/`

**Q10：Windows 什么时候支持？**

已列入 v0.2.0 路线图。约 80% 的代码（扫描 / 清理 / 归档 / 重复检测 / Reveal）已经跨平台，主要差距在「编辑器/终端启动」逻辑。如果你有具体使用场景，欢迎去 [Issues](https://github.com/szgenle/devzen/issues) 留言，会直接影响排期。
